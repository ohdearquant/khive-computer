# Working on khive computer

This file is for anyone changing the code: a person, or an agent reading it as its instructions
(`CLAUDE.md` imports it). Using a computer is `GUIDE.md`; what the computer holds is `docs/SPEC.md`;
why it is shaped this way is `docs/adr/INDEX.md`.

> From `GUIDE.md`:
> "A ref moves only by compare-and-swap: you name the tree you started from, and if someone moved
> the ref first the move refuses and tells you the tree it found. Read again, redo your edit on that
> tree, move again."

That sentence is the whole design in one place. Every change here keeps it true.

## Setup

```sh
uv sync                              # the package, pytest, ruff, pre-commit
uv run pre-commit install            # once; the hooks below then run on every commit
uv run pytest -q                     # the suite, about ten seconds
uv run pre-commit run --all-files    # everything CI runs, locally
docker build -t khive-computer:dev . # the base image users run
uv run kc build --rust --node --base khive-computer:dev -t khive-computer:tools   # the toolchain layers on it
E2E_IMAGE=khive-computer:dev E2E_TOOLS_IMAGE=khive-computer:tools uv run pytest -q tests/test_docker.py   # both, end to end
```

Python 3.12 or newer. `git` on PATH. Docker only for the image and the `docker` sandbox.

## Layout

| path | holds |
| --- | --- |
| `src/khive_computer/blobs.py`, `trees.py` | the content store and trees as values |
| `src/khive_computer/db/` | the SQLite file: `schema.sql` (every table, commented), `connect` (WAL, pragmas, schema applied), and every statement, one module per table (`seats`, `refs` with the compare-and-swap, `snapshots`, `actions`, `events`, `repos`) |
| `src/khive_computer/computer.py` | `Computer`: the data directory, blobs and trees, the connection and the one lock; every method calls a `db/` function |
| `src/khive_computer/fs.py` | path views and functional edits over trees |
| `src/khive_computer/execer.py` | actions: key, cache, slots, sandboxes, the action user, the free-space floor |
| `src/khive_computer/gitio.py` | git at the edge: import, export, push, log; the credential helper |
| `src/khive_computer/merge.py` | three-way merge of trees |
| `src/khive_computer/server.py` | the eight MCP tools, `family` dispatch, seat auth, events |
| `src/khive_computer/image.py` | `kc build`: the Dockerfile for a toolchain image, generated and built on stdin |
| `src/khive_computer/local.py` | deployments in this machine's Docker: `kc build -n` (record + token), `up`, `down`, `purge`, `prune`, `ps` |
| `src/khive_computer/cli.py` | `kc`: build, up, down, purge, prune, ps, seat (`--in` for a deployment), init, import, serve (reads `KC_SEAT_TOKEN`), mcp-config, metrics |
| `tests/` | `test_core.py` on the computer and executor, `test_server.py` over real HTTP, `test_docker.py` against a real container (needs `E2E_IMAGE`) |
| `docs/SPEC.md`, `docs/adr/`, `docs/DEPLOY.md` | the surface, the decisions, running it for others |
| `scripts/check_docs.py` | documents against code; runs in pre-commit and CI |

## Rules for a change

1. **The surface is eight tools; verbs are actions.** A new verb is a handler added to its family's
   table at the bottom of `server.py`. It gets no tool of its own. A verb that fits no family needs a
   record amending ADR-0007 before the ninth tool exists. Handlers take plain arguments and return a
   dict or a list; the dispatcher does the auth, the event and the error shape.
2. **A claim marked mechanical names the test that pins it; a change that breaks the claim breaks
   the test, and a change that moves the surface updates SPEC.md, the family's record and the tests
   in the same commit.** `scripts/check_docs.py` refuses a documented verb that is not registered, a
   registered verb no document names, an environment variable only one side knows, a cited test that
   does not exist, and a wikilink that resolves to nothing.
3. **Records follow one format.** `docs/adr/NNN-topic/ADR-NNNN-slug.md`: YAML front matter (`adr`,
   `status`, `liveness`, `date`, `area`, `kind`, `depends_on`, `tags`), then Context, Definitions,
   Assumptions (a table), Claims (`### Cn: ... _(enforced: mechanical|by convention)_ ^cn` with Subject
   and Violated-when bullets), Decisions (`### Dn ^dn`, Serves, Landing evidence), Alternatives (a
   table), Consequences (`S1...`). `mechanical` only with a test name or a code path you can point at.
   `docs/adr/INDEX.md` is generated by `docs/adr/_scripts/gen_adr_index.py`; never edit it by hand.
4. **Write a verb as `family.action`** in every document (`ref.move`, `branch.merge`). The tool on the
   wire is the family name with `action="..."`; tool names cannot carry a dot.
5. **Nothing private in the tree.** No real email addresses in fixtures (use `example.com`), no
   hosting-account names, no tokens. The committer identity is `KC_GIT_IDENTITY`, not a constant with
   somebody's domain in it.
6. **Trees are values; the store only grows.** Nothing deletes a blob. A change that would rewrite or
   remove content needs a record, not a flag.
7. **Markdown lints.** Lines up to 120 characters outside tables and code, blank lines around lists
   and fences, a language on every fence. `markdownlint-cli2` runs in pre-commit with
   `.markdownlint-cli2.jsonc`.

## What CI runs

`.github/workflows/ci.yml`: the pre-commit hooks on all files, pytest on Python 3.12 and 3.13, and
a build of the image without pushing it, followed by `tests/test_docker.py` against that build (the first
seat minted on the volume, `/healthz`, the tools over MCP, a rotated token, stop and recreate on the same
volume). `.github/workflows/image.yml` publishes the image to GHCR on pushes to `main` and on `v*` tags.
A pull request is mergeable when all three jobs are green.

## Where to read first

A change to a table or a statement: `db/schema.sql`, then the table's module in `db/`, then the record that
owns the table (ADR-0001 refs and snapshots, ADR-0002 actions, ADR-0003 seats and events). A change to actions:
`docs/adr/002-action/ADR-0002-the-action.md`, then `execer.run`. A change to
the surface: ADR-0007, then `family` in `server.py`. A change to git: ADR-0004, then `gitio.py`. A
change to how it is deployed, or to what a host reads from the computer: ADR-0008, then
`docs/DEPLOY.md`, `Dockerfile`, `compose.yaml`.
